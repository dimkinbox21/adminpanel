# Авто-аим на киллера и панель «сзади» — разбор изменений

> Документ объясняет два новых модуля в `AdminMenu.client.lua`: **постоянный
> авто-аим на киллера** и **панель «сзади»** в правом нижнем углу. Читается
> сверху вниз; новичку по Roblox пригодится раздел «Контекст», знающему его
> можно пропустить.

## Контекст

Весь проект — это один LocalScript на ~5.7 тыс. строк, который кладётся в
`StarterPlayer → StarterPlayerScripts`. Он рисует своё меню поверх игры и
добавляет клиентские функции: полёт, noclip, ESP, автоблок, предупреждение о
киллере и т.д. Каждая функция — это «тумблер» (feature) с состоянием в таблице
`state`, клавишей в таблице `BINDS` и настройками в отдельной таблице-конфиге
(`FLY`, `ESP`, `WARNING`…). Настройки сохраняются в JSON-профиль.

Для новичка важны три факта про Roblox:

- **Камера** — это объект `workspace.CurrentCamera`. Штатный скрипт камеры
  каждый кадр пересчитывает её `CFrame` (позиция + поворот) по движению мыши.
  Кадровый цикл упорядочен приоритетами: `RunService:BindToRenderStep(name,
  priority, fn)` вызывает `fn` в заданной точке кадра, а камера обновляется на
  приоритете `Enum.RenderPriority.Camera` (200).
- **Кто где** — в этом плейсе персонажи лежат в
  `workspace.GameAssets.Teams.<Команда>`, поэтому команду игрока определяет уже
  существующая функция `teamNameOf`, а киллер — это
  `teamNameOf(...) == KILLER_TEAM`.
- **Лимит Luau**: компилятор разрешает не больше **200 локальных переменных**
  на верхнем уровне функции. Файл уже упёрся в этот предел — поэтому вся работа
  с конфигом обёрнута в `do ... end` (локалы внутри блока освобождаются на
  выходе).

> [!WARNING]
> Этот лимит — не абстракция: наивная реализация (по 5–6 новых локалов верхнего
> уровня на фичу) **не компилируется**. Ниже видно, как это обошли.

## Интуиция

**Авто-аим.** Идея на пальцах: каждый кадр находим ближайшего живого киллера,
берём точку его головы `P`, позицию камеры `C` и ставим камере поворот «смотреть
из `C` в `P`»:

> Игрушечный пример: камера в точке `C=(0,5,0)`, киллер за спиной в `P=(0,5,20)`.
> `CFrame.lookAt(C, P)` развернёт камеру на 180° — киллер оказывается в центре
> экрана. На следующем кадре киллер сместился — пересчитали, снова в центре.
> Это и есть «лок».

Единственная тонкость — **порядок в кадре**. Если наш поворот записать *до*
штатной камеры, та сразу перезапишет его обратно к мыши, и лок будет «мигать».
Поэтому мы встаём на приоритет `Camera + 1` — строго *после* камеры.

**Панель «сзади».** «Сзади» — это геометрия. Берём горизонтальный вектор
взгляда `look`. Для каждого игрока считаем направление на него `dir`. Скалярное
произведение `look·dir` говорит, спереди он (`> 0`) или сзади (`< 0`).

> Игрушечный пример: смотрю вдоль `look=(0,0,-1)`. Игрок сзади даёт
> `dir≈(0,0,1)`, `look·dir=-1` — глубоко за спиной. Игрок сбоку даёт
> `look·dir≈0`. Порог `Angle=100°` пускает в панель всех, у кого
> `look·dir ≤ -cos(100°) ≈ 0.17`, то есть заднюю полусферу плюс чуть-чуть по
> бокам.

Сторону (лево/право) даёт второе скалярное произведение — с вектором «вправо»
камеры. А «что происходит» — это тренд: сравниваем дистанцию с прошлым замером;
уменьшается — приближается (красный), растёт — отдаляется (зелёный).

## Код

Всё новое состояние спрятано в **один** контейнер-локал `X`, чтобы не
переполнить 200 регистров:

```lua
-- Контейнер авто-аима и панели "сзади". Один локал верхнего уровня
-- вместо десятка, чтобы не упереться в лимит регистров.
local X = {}
X.aimbot = { MaxDistance = 250, Smoothness = 1, AimHead = true, VisibleOnly = false, ... }
X.rear = { MaxDistance = 140, Angle = 100, OnlyThreats = false, Epsilon = 1.5, ... }
```

Авто-аим: захват висит на `BindToRenderStep` с приоритетом `Camera + 1`, а сам
шаг проверяет флаг `state.aimbot`, ищет ближайшего киллера и разворачивает
камеру:

```lua
local goal = CFrame.lookAt(camPosition, part.Position)
if X.aimbot.Smoothness <= 1 then
	camera.CFrame = goal                                   -- жёсткий лок
else
	camera.CFrame = camera.CFrame:Lerp(goal, 1 / X.aimbot.Smoothness) -- мягче, с отставанием
end
-- ...
RunService:BindToRenderStep("AdminAimbot", Enum.RenderPriority.Camera.Value + 1, step)
```

Опция «Только по видимым» — луч от камеры к цели; если первым встретилась чужая
геометрия, а не сам киллер, значит он за стеной и мы не наводимся:

```lua
local hit = workspace:Raycast(origin, delta, rayParams)
if not hit then return true end
return hit.Instance:IsDescendantOf(killerChar)
```

Панель «сзади»: критерий заднего сектора — одно сравнение скаляров:

```lua
local rearThreshold = -math.cos(math.rad(X.rear.Angle))
-- ...
if flatLook:Dot(dirUnit) <= rearThreshold then
	-- он сзади: считаем сторону (flatRight:Dot(dirUnit)) и тренд по истории дистанций
end
```

Панель повторяет приём списка игроков — **пул строк** (метки не пересоздаются
каждый кадр) и обновление 10 раз в секунду по таймеру в `RenderStepped`. Обе
фичи добавлены как обычные тумблеры в таблицу `FEATURES`, получили бинды `X` и
`C`, вкладку «Аим» в меню и полную поддержку сохранения/сброса конфига.

> [!NOTE]
> Всё, что торчит наружу из `do`-блоков, — это поля контейнера:
> `X.applyAimbot`, `X.applyRear`, `X.updateRear`, `X.rearAccum`. Ни одного
> лишнего локала верхнего уровня.

## Проверка

Локально установить Roblox-движок нельзя, поэтому проверка — это **компиляция
официальным Luau** (тот же компилятор, что в Roblox) и статический анализ:

- `luau-compile -O1` и `-O2` (уровни, которые использует Roblox) — **успех**.
  При этом на `-O0` файл не компилируется — но так было и до изменений: это
  ожидаемо и к рантайму отношения не имеет.
- `luau-analyze` — единственные замечания это «Unknown global» для `Enum`,
  `Vector3`, `workspace`, `RaycastParams` и т.п. Это ожидаемый шум: без типов
  Roblox анализатор не знает эти глобалы. Реальных ошибок в новом коде нет.

**Как отQA-ить руками в игре:**

1. Запусти файл через executor, зайди в раунд как выживший.
2. Открой меню (`RightCtrl`) → вкладка **Аим** → включи «Авто-аим». Камера
   должна держать ближайшего киллера в центре. Покрути мышь — камера
   возвращается на цель (жёсткий лок при «Плавность = мгновенно»).
3. Подними «Плавность» до 5–8 — камера ведёт цель мягче, с лёгким отставанием.
4. Включи «Только по видимым» и зайди за стену — наводка должна отпустить, пока
   киллер не в прямой видимости.
5. Включи «Панель сзади» (`C`). Встань к киллеру спиной — он появится сверху
   панели с ⚠, дистанцией, стороной (`←/→/•`) и цветом тренда (красный при
   сближении). Развернись — панель очистится («чисто»).
6. Поменяй «Радиус»/«Ширина сектора»/«Только киллер», сохрани профиль на вкладке
   «Конфиг», перезапусти скрипт — значения должны подтянуться.

## Альтернативы

| Решение | За | Против |
| --- | --- | --- |
| **Авто-аим: писать камеру в общем `RenderStepped`, а не в `BindToRenderStep(Camera+1)`** | Меньше кода, всё в одном цикле | Порядок относительно штатной камеры не гарантирован — лок «мигает», когда камера перезаписывает наш поворот в том же кадре. Именно поэтому выбран приоритет `Camera + 1`. |
| **Панель «сзади»: настоящее зеркало через `ViewportFrame`** | Визуально показывает саму сцену за спиной | `ViewportFrame` рендерит только объекты, вручную вклонированные в него, — карту и свет он не покажет; клонирование моделей каждый кадр дорого и хрупко. Текстовая панель дешевле, надёжнее и сразу даёт дистанцию/сторону/тренд. |

## Квиз

<details>
<summary>1. Почему авто-аим стоит на приоритете <code>Camera + 1</code>, а не просто в <code>RenderStepped</code>?</summary>

а) Так быстрее • **б) Чтобы записать камеру ПОСЛЕ штатного скрипта камеры** • в) Требование Luau • г) Ради экономии локалов

**Верно: б.** Штатная камера пересчитывает `CFrame` на приоритете Camera; если
писать раньше — она перезапишет наш поворот и лок будет мигать. `Camera + 1`
гарантирует, что мы последние в кадре.
</details>

<details>
<summary>2. Какое условие определяет, что игрок «сзади»?</summary>

а) `flatLook:Dot(dirUnit) <= -cos(Angle)` • б) `distance < 0` • в) `dir.Y < 0` • г) `flatRight:Dot(dirUnit) > 0`

**Верно: а.** Задний сектор — это угол от направления «прямо за спиной»
(`-look`); в скалярном виде получается `look·dir ≤ -cos(Angle)`. Вариант «г»
задаёт сторону (право), а не «сзади».
</details>

<details>
<summary>3. Зачем все новые данные сложены в один контейнер <code>X</code>?</summary>

а) Красивее • б) Быстрее выполняется • **в) Чтобы не превысить лимит в 200 локалов верхнего уровня** • г) Так требует JSON

**Верно: в.** Отдельные локалы под каждую таблицу/функцию переполняли лимит
регистров Luau (файл и так на грани). Один контейнер = один локал верхнего
уровня.
</details>

<details>
<summary>4. Что делает «Плавность = 1» против «Плавность = 8»?</summary>

а) Меняет радиус • **б) 1 — мгновенный лок, 8 — камера доворачивается через Lerp за несколько кадров** • в) Отключает аим • г) Целится в корпус вместо головы

**Верно: б.** При `Smoothness <= 1` камера ставится сразу в цель; больше —
`Lerp` с шагом `1/Smoothness`, движение мягче, но с отставанием.
</details>

<details>
<summary>5. Как в панели определяется, что цель «приближается» (красный)?</summary>

а) По здоровью • б) По стамине • **в) По знаку изменения дистанции между замерами с порогом Epsilon** • г) По команде

**Верно: в.** Панель хранит прошлую дистанцию (в таблице со слабыми ключами) и
сравнивает: падает быстрее `Epsilon` — приближается (красный), растёт —
отдаляется (зелёный), иначе держит дистанцию (серый).
</details>
